# مرکز آموزش مدل Locomotive Analyzer

این پوشه تمام ابزارهای آموزش مدل را مستقل از اجرای اپلیکیشن نگه می‌دارد.

## اجزای این پوشه

| فایل | کاربرد |
|---|---|
| `colab_train.ipynb` | آموزش در Google Colab؛ بدون نیاز به نصب محیط توسعه روی سیستم شخصی |
| `local_trainer.py` | رابط گرافیکی دسکتاپ برای انتخاب فایل Excel، شروع آموزش و مشاهده لاگ |
| `TRAIN_LOCAL.bat` | راه‌انداز ویندوز؛ ساخت محیط مجازی، نصب وابستگی‌ها و اجرای رابط گرافیکی |
| `train_model.py` | هسته مشترک آموزش، ارزیابی و تبدیل به ONNX |
| `output/` | گزارش معیارها و پیش‌بینی‌های بخش آزمون (به‌صورت محلی تولید می‌شود) |
| `data/` | محل قرار دادن دیتاست (در Git ثبت نمی‌شود) |

## آموزش لوکال در Windows

1. مخزن را به‌روز کن و وارد پوشه پروژه شو.
2. فایل Excel دیتاست را انتخاب کن؛ مسیر پیشنهادی `training/data/LocomotivDataSet.xlsx` است.
3. فایل `training/TRAIN_LOCAL.bat` را اجرا کن.
4. در پنجره بازشده، فایل Excel را انتخاب و روی **Start training** کلیک کن.
5. لاگ آموزش زنده نمایش داده می‌شود. پس از موفقیت، این خروجی‌ها ساخته/به‌روزرسانی می‌شوند:
   - `public/models/locomotive_model.onnx`
   - `public/models/metadata.json`
   - `backend/models/model_bundle.zip` (بسته آماده نصب در برنامه)
   - `training/output/evaluation_report.json`
   - `training/output/evaluation_predictions.csv`
   - همین فایل README، در بخش «آخرین گزارش آموزش»

نیازمندی: Python 3.11 یا جدیدتر. آموزش فعلی روی CPU انجام می‌شود و GPU لازم ندارد. برای لپ‌تاپ‌های قدیمی ممکن است آموزش زمان‌بر باشد. پیش از شروع، دستگاه را به برق وصل کن و مطمئن شو پردازنده درگیر محدودیت توان یا دمایی شدید نیست.

### اجرای خط فرمان (جایگزین رابط گرافیکی)

از ریشه مخزن:

```powershell
python training/train_model.py --dataset "training/data/LocomotivDataSet.xlsx"
```

## آموزش با Google Colab

1. فایل `colab_train.ipynb` را در GitHub باز کن و گزینه **Open in Colab** را انتخاب کن؛ یا فایل Notebook را دانلود و در Colab بارگذاری کن.
2. سلول‌ها را به‌ترتیب اجرا کن.
3. در سلول آپلود، فایل `LocomotivDataSet.xlsx` را انتخاب کن.
4. Notebook همان اسکریپت آموزش مخزن را اجرا می‌کند و بسته ZIP، گزارش JSON و README به‌روز‌شده را برای دانلود آماده می‌کند.

در هر دو محیط، هسته آموزش یکسان است تا نتایج حاصل از اجرای محلی و Colab قابل مقایسه باشند.

## داده، ویژگی‌ها و هدف

شیت مورد استفاده: `گزارش روزانه`

ویژگی‌های ورودی به همین ترتیب:
1. وضعیت سیر قبل (۱=سالم، ۰=خراب)
2. روز از آخرین خرابی در سیر
3. زمان تعمیرات امروز (ساعت)
4. هزینه تعمیر (یورو)

متغیر هدف: `قابلیت سیر امروز`

تاریخ و شماره لکوموتیو در نسخه فعلی جزو ویژگی‌های مدل نیستند. در نتیجه مدل فعلی یک مدل جدولی است و توالی زمانی لکوموتیوها را مستقیماً یاد نمی‌گیرد.

## پارامترهای مهم برای مطالعه

| پارامتر | مفهوم |
|---|---|
| نسبت آموزش/آزمون | سهم داده‌ای که برای fit و ارزیابی کنار گذاشته می‌شود |
| `random_state` | ثابت نگه‌داشتن تقسیم تصادفی برای مقایسه تکرارپذیر |
| `n_estimators` | تعداد درخت‌های Random Forest؛ بیشتر بودن الزاماً بهتر نیست |
| `max_depth` | حداکثر عمق هر درخت؛ کنترل پیچیدگی و بیش‌برازش |
| `min_samples_leaf` | حداقل تعداد نمونه در برگ؛ مقدار بیشتر معمولاً مدل را هموارتر می‌کند |
| `max_leaf_nodes` | سقف تعداد برگ‌ها؛ محدودکننده اندازه مدل |
| `max_features` | تعداد/سهم ویژگی‌های بررسی‌شده در هر split |
| MAE | میانگین قدرمطلق خطا؛ کمتر بهتر |
| RMSE | ریشه میانگین مربع خطا؛ خطاهای بزرگ را بیشتر جریمه می‌کند |
| R² | میزان توضیح تغییرات هدف نسبت به baseline میانگین؛ در ارزیابی استاندارد نزدیک ۱ بهتر است |

پارامترهای فعلی مدل در تابع `make_model()` داخل `train_model.py` تعریف شده‌اند. هر تغییر معماری یا پارامتر باید در گزارش خودکار بعدی منعکس شود.

## کتابخانه‌های کلیدی

- **pandas / openpyxl**: خواندن و آماده‌سازی فایل Excel
- **NumPy**: محاسبات عددی و پاک‌سازی مقادیر نامعتبر
- **scikit-learn**: مدل Random Forest، تقسیم داده، baseline و معیارهای ارزیابی
- **skl2onnx**: تبدیل مدل scikit-learn به ONNX
- **ONNX**: قالب قابل‌انتقال مدل
- **ONNX Runtime**: اجرای مدل در Backend برنامه (مرحله inference)

نسخه دقیق کتابخانه‌های نصب‌شده پس از هر آموزش موفق در گزارش خودکار ثبت می‌شود.

## روش ارزیابی فعلی و هشدارها

- تقسیم فعلی: تصادفی با نسبت ۸۰٪ آموزش و ۲۰٪ آزمون و seed برابر ۴۲.
- مدل ارزیابی فقط روی بخش آموزش fit می‌شود و معیارها روی بخش آزمون محاسبه می‌شوند.
- یک `DummyRegressor(strategy="mean")` به‌عنوان baseline گزارش می‌شود.
- پس از ارزیابی، مدل نهایی برای استقرار روی تمام ردیف‌های معتبر fit می‌شود.
- این روش برای مقایسه فنی اولیه است؛ به دلیل ساختار زمانی و شناسه لکوموتیو، ارزیابی زمانی و جداسازی لکوموتیوها باید در مراحل بعدی بررسی شود تا نشت داده رخ ندهد.
- مستندات دیتاست فعلی آن را مصنوعی/تصادفی توصیف می‌کند. بنابراین هیچ عددی در این گزارش به‌تنهایی اثبات‌کننده دقت عملیاتی در پیش‌بینی خرابی واقعی نیست.
